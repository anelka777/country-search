# DESIGN

Живой поиск стран по имени (`countries.dev`). Документ объясняет, как решена гонка устаревших ответов, почему выбраны именно такие задержки, какова сложность преобразования данных и какие принципы чистого кода применены.

## 1. Отмена устаревших запросов

### Проблема

Пользователь печатает `spain` по буквам. Ответ на `sp` может прийти позже ответа на `spain` и перезаписать на экране правильный результат старым. Без явной отмены это вопрос времени.

### Как устроено

- `src/searchController.ts` хранит `currentRequest` — `AbortController` запроса, который сейчас в полёте.
- Первая строка `input()` — `cancelCurrentRequest()`. Отмена происходит **на каждое изменение ввода**, ещё до debounce, а не в момент, когда debounce запускает новый запрос. Иначе за время ожидания debounce устаревший ответ успел бы прийти и отрисоваться под новым текстом.
- `runSearch()` создаёт **новый** `AbortController` на каждый запрос. Один общий контроллер нельзя: после первого `abort()` все следующие сигналы рождались бы уже отменёнными.
- `searchCountries(query, signal)` (`src/searchCountries.ts`) объединяет сигнал вызывающего с таймаутом: `AbortSignal.any([signal, AbortSignal.timeout(timeoutMs)])`, и передаёт его в `fetch`.
- Когда на сигнале вызван `abort()`, промис `fetch` отклоняется с `AbortError`, и устаревший ответ до состояния приложения не доходит.

### Различение ошибок

`src/classifyError.ts` разбирает пойманную ошибку по полю `name`:

| Что пришло                                      | Вид         | Что видит пользователь                                     |
| ----------------------------------------------- | ----------- | ---------------------------------------------------------- |
| `AbortError` (свой же `abort()`)                | `cancelled` | ничего: это не ошибка, `catch` в контроллере молча выходит |
| `TimeoutError` (сработал `AbortSignal.timeout`) | `timeout`   | ошибка и кнопка «Повторить»                                |
| `HttpError` (статус не 2xx и не 404)            | `http`      | ошибка и кнопка «Повторить»                                |
| всё остальное (обрыв сети)                      | `network`   | ошибка и кнопка «Повторить»                                |

404 обрабатывается раньше, внутри `searchCountries`: `countries.dev` отвечает 404, когда совпадений нет. Это не ошибка, функция возвращает `[]`, контроллер переходит в состояние `empty`, и до `catch` статус 404 не доходит. Остальные неуспешные статусы определяются проверкой `response.ok` (`fetch` сам не бросает исключение на 4xx/5xx) и превращаются в `HttpError`.

### Почему не флаг «актуальный ли это ответ»

Флаг (или сравнение с последним запросом) только скрывает результат устаревшего ответа, но сам запрос продолжает жить:

- браузер всё равно скачивает и разбирает ответ, тратя трафик и процессорное время;
- запросы занимают лимит параллельных соединений, а на медленной сети мешают актуальному;
- проверка «актуальности» размазывается по коду: каждое место, где ответ используется, должно её помнить, и забыть её легко;
- асинхронность остаётся неявной: устаревший промис по-прежнему завершается успешно, просто его результат игнорируется.

С `AbortController` старый запрос реально прекращается, а его промис отклоняется. Устаревшие данные просто не могут попасть в состояние, потому что они не приходят.

Ограничение: `abort()` обрывает запрос на стороне клиента. Сервер мог уже начать обработку, и мы не можем это остановить.

### Таймаут

У `fetch` нет управляемого таймаута: встроенные ограничения браузера длинные и непредсказуемые, и из кода их не настроить. `DEFAULT_TIMEOUT_MS = 8000` (8 секунд) — компромисс: меньшее значение будет ложно срабатывать на медленной сети, большее оставит человека смотреть на индикатор загрузки слишком долго. Таймаут отличается от своей отмены именем ошибки (`TimeoutError` против `AbortError`), поэтому пользователь видит ошибку только в первом случае.

### Как проверено

- `tests/raceCondition.test.ts`: настоящие контроллер и `searchCountries`, подменён только `fetch`. Мок реагирует на `signal` и отклоняется с `AbortError`, а ответ на `sp` приходит после ответа на `spain`. В итоговом состоянии — только результат по `spain`. Тест проверен «на прочность»: при отключённой строке `cancelCurrentRequest()` он падает.
- `tests/searchController.test.ts`: отмена сразу при новом вводе (до срабатывания debounce), отмена при очистке поля, свой сигнал на каждый запрос.
- `tests/searchCountries.test.ts`, `tests/classifyError.test.ts`: `TimeoutError` и `AbortError` не путаются.

## 2. Задержка debounce

В `src/searchController.ts` задана константа `DEFAULT_DEBOUNCE_MS = 300`. Саму функцию `debounce` (`src/debounce.ts`) написал я: на каждый вызов она сбрасывает таймер, и `fn` вызывается с аргументами последнего вызова. Есть метод `cancel()`, он нужен, чтобы очистка поля отменяла уже запланированный запрос.

- **Если убрать задержку:** запрос уходил бы на каждую букву. Для `spain` это пять запросов, из них четыре сразу отменяются. Лишняя нагрузка на сеть и сервер, и индикатор загрузки мигает на каждом нажатии.
- **Если сильно увеличить** (например, до 1500 мс): приложение кажется «зависшим», пользователь печатает и не понимает, ищется ли что-то.
- **Почему 300 мс:** значение достаточно мало, чтобы отклик ощущался мгновенным, и достаточно велико, чтобы пережидать обычные паузы между нажатиями при наборе слова. Это распространённое значение для живого поиска.

Важно: корректность (никаких устаревших результатов) обеспечивает **отмена запроса**, а не debounce. Debounce лишь снижает число запросов и улучшает ощущение от интерфейса, поэтому его значение можно менять без риска получить гонку.

## 3. Сложность (Big O)

### `mapCountryResponse` (`src/mapCountryResponse.ts`)

Для одной страны пусть `L` — число языков, `C` — число валют, `B` — число границ.

- Поля `name`, `region`, `population`, `capital`, `area`, `flag` копируются за O(1).
- `languages` и `currencies` обходятся один раз через `.map`: O(L) и O(C).
- `borders` копируется один раз: O(B).
- `description` собирается конкатенацией строк: O(длины названия и подрегиона).

**Итого для одной страны: O(L + C + B)** времени и столько же дополнительной памяти (новые массивы). У реальных стран эти числа ограничены небольшими константами (единицы или десятки элементов), поэтому на практике это O(1) на страну.

**Для списка из `n` стран:** `searchCountries` применяет функцию через `.map`, получается **O(n · (L + C + B))**, то есть O(n) при ограниченных `L`, `C`, `B`. Сеть и отрисовка дороже преобразования на порядки.

Вложенных циклов нет, каждое поле читается один раз.

## 4. Принципы чистого кода

| Принцип                             | Где применён                                                                                                                                                                                                                                                                                |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Единственная ответственность**    | Каждый файл делает одно: `debounce.ts` откладывает вызов, `searchCountries.ts` ходит в сеть, `classifyError.ts` классифицирует ошибку, `mapCountryResponse.ts` преобразует данные. Внутри `mapCountryResponse.ts` мелкие `formatCurrency` и `buildDescription` вынесены в отдельные функции |
| **Чистые функции**                  | `mapCountryResponse` и `classifyError` не обращаются к сети, времени и DOM и не меняют аргументы (`borders` копируется, это проверяет тест `does not mutate the input`). Поэтому они тестируются без моков                                                                                  |
| **Логика отделена от DOM**          | `searchController.ts` ничего не знает про страницу и общается только через `onStateChange`. Интерфейс (`views.ts`, `main.ts`) лишь рисует состояния. Благодаря этому поиск, отмена и ошибки проверяются тестами в терминале без браузера                                                    |
| **Внедрение зависимостей**          | `createSearchController({ search, onStateChange, debounceMs })` принимает поиск и обработчик снаружи. В тестах вместо сети подставляется шпион                                                                                                                                              |
| **Без «магических чисел»**          | Имена вместо литералов: `NOT_FOUND`, `API_URL` (`searchCountries.ts`), `DEFAULT_TIMEOUT_MS`, `DEFAULT_DEBOUNCE_MS`                                                                                                                                                                          |
| **Типы вместо проверок в рантайме** | `SearchState` — объединение с полем `status`; `renderState` (`views.ts`) разбирает его через `switch` без `default`, и TypeScript сообщит, если добавить состояние и не обработать его. `Record<ErrorKind, string>` требует текст для каждого вида ошибки                                   |
| **Ранний выход**                    | `classifyError` и `input` проверяют частные случаи и сразу возвращают результат, без глубокой вложенности                                                                                                                                                                                   |
| **Свой тип ошибки**                 | `HttpError` (`httpError.ts`) хранит `status`, поэтому по нему можно отличить ошибку сервера от прочих                                                                                                                                                                                       |
| **Безопасная работа с DOM**         | Элементы создаются через `h()` (`dom.ts`) и `createElement`; текст вставляется как текст, `innerHTML` не используется, что исключает XSS                                                                                                                                                    |
| **Без повторения**                  | Помощник `h()` заменяет повторяющийся код создания элементов                                                                                                                                                                                                                                |

## Процесс

Для `debounce`, `mapCountryResponse`, `searchCountries` и логики различения ошибок сначала написаны тесты отдельным коммитом (красный), затем реализация (зелёный). Тест гонки добавлен отдельным коммитом после базовой логики.
